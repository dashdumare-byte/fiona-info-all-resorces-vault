# Quantum Layer

> **D-Wave Leap primary (annealing optimization). Origin Pilot secondary (gate-model research).**

---

## D-Wave Leap (Primary)

| Attribute | Value |
|-----------|-------|
| **Qubits** | 5,000+ (Advantage) |
| **Type** | Quantum Annealing |
| **Cost** | FREE for 3 months (LaunchPad), then $129/month |
| **API** | Python SDK |
| **Apply** | dwavesys.com/quantum-launchpad |

### What It Brings

| Capability | Description | Example |
|------------|-------------|---------|
| **Optimization** | Global optimum for complex problems | "Best camera placement for 12 shots" — classical tries 100 combos, quantum tries 10^6 simultaneously |
| **Pattern Recognition** | Non-obvious patterns across research | 3 models mention 'asymmetry' independently -> quantum confirms statistical significance |
| **Strategy Guidance** | Optimal approach via combinatorial analysis | Analyzes 50 material properties + 30 geometry constraints for dental grillz |
| **Rubric Enforcement** | Multi-objective optimization scoring | "Module scores 0.92 functionality but 0.65 performance -> suggests trade-offs" |
| **Resource Allocation** | Optimizes API budget per module | "Module 45 needs more visual analysis -> allocate 30% more Opus 4.8 tokens" |

### Strategy Briefs to Each Model

Quantum provides targeted guidance:
- **To Opus 4.8**: "Focus on visual asymmetry, quantum confirms this pattern"
- **To GPT-5.5**: "Adversarial check: quantum found edge case in tolerance logic"
- **To V4-Pro**: "Community fix #47 is optimal, quantum validated"
- **To GLM-5.2** (GLM-5.1 fallback): "Use iterative refinement, quantum shows 3-pass is optimal"

### If D-Wave Fails
1. NOTIFY Ashandy
2. PAUSE build
3. Switch to Origin Pilot
4. Cannot proceed without Ashandy approval

## Origin Pilot (Secondary)

| Attribute | Value |
|-----------|-------|
| **Qubits** | 72 (Wukong) |
| **Type** | Gate-model quantum computing |
| **Cost** | FREE |
| **API** | QPanda3 |
| **Status** | BACKUP / RESEARCH ONLY |

### What It Does Differently
- D-Wave = Annealing (optimization-focused)
- Origin = Gate-model (general quantum computing, like IBM/Qiskit)

### Use Cases
| Priority | Use |
|----------|-----|
| 1 | Backup: If D-Wave fails, handles basic optimization |
| 2 | Research: Testing quantum algorithms for future Fiona versions |
| 3 | Education: Learning quantum computing (free, no credits) |
| 4 | Experimental: Quantum machine learning for taste learning |

### Limitations
- Only 72 qubits vs D-Wave's 5,000+
- Gate-model is harder to program
- Slower for optimization problems
- Entity List issues (US restrictions)

### If Origin Also Fails
1. NOTIFY Ashandy AGAIN
2. Build CANNOT proceed without approval
3. Options: Extend timeline, switch to classical approximation, debug quantum connection
